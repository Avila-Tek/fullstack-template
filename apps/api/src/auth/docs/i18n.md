# Auth Module — i18n

## Locale detection logic

Locale is detected per-request from the `Accept-Language` HTTP header by `detectLocale` in `src/infrastructure/i18n/locale.ts`.

1. If the header is absent, the locale defaults to `es`.
2. The first language tag in the header is extracted (before `,` and `;`).
3. If the tag starts with `en` (case-insensitive), the locale is `en`.
4. Otherwise, the locale is `es`.

There is no cookie or user-preference override — locale is always derived from the request header.

## Supported locales

| Code | Language |
|---|---|
| `es` | Spanish (default) |
| `en` | English |

## How to add a new language

1. Add the new locale code to the `Locale` type in `src/infrastructure/i18n/locale.ts`:
   ```ts
   export type Locale = 'en' | 'es' | 'fr';
   ```
2. Add a detection branch in `detectLocale`:
   ```ts
   if (primary.startsWith('fr')) return 'fr';
   ```
3. Add a translation record for the new locale in both message catalogs:
   - `src/infrastructure/i18n/better-auth-messages.ts`
   - `src/infrastructure/i18n/domain-messages.ts`
4. The `betterAuthMessage` function falls back to `es` if a code is missing from the requested locale, so partial translations are safe during a rollout.
